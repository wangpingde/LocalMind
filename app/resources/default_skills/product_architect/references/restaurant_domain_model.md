# 餐饮数字化领域对象与状态模型

## 核心领域对象

| 领域 | 核心对象 | 关键关系 |
|------|----------|----------|
| 组织 | 租户、品牌、区域、门店、岗位、员工、加盟商 | 租户拥有品牌，品牌管理门店，门店绑定员工与设备 |
| 商品 | 菜品、SKU、规格、加料、套餐、配方、分类、菜单 | 菜品可多规格，菜单可按门店/渠道/时段生效 |
| 交易 | 购物车、订单、订单项、支付单、退款单、发票 | 订单关联支付与退款，订单项关联菜品快照 |
| 履约 | 桌台、排队号、KDS 工单、出餐任务、配送任务 | 订单生成履约任务，任务驱动后厨与配送 |
| 营销 | 会员、积分、储值、券、活动、权益、核销记录 | 活动发放权益，权益在订单中核销 |
| 供应链 | 原料、库存、采购单、调拨单、盘点单、损耗单 | 配方驱动库存扣减，门店库存支撑销售 |
| 财务 | 交接班、日结、对账单、渠道结算、佣金、成本 | 支付、退款、外卖渠道和库存成本进入财务口径 |

## 高风险状态机

### 订单

创建中 -> 待支付 -> 已支付 -> 制作中 -> 待取餐/配送中 -> 已完成

可逆/异常状态：已取消、退款中、部分退款、已退款、履约失败、人工关闭。

### 支付

待发起 -> 支付中 -> 支付成功 -> 对账成功

异常状态：支付失败、支付超时、重复回调、金额不一致、待人工确认。

### 退款

申请中 -> 审核通过 -> 退款处理中 -> 退款成功

异常状态：审核拒绝、退款失败、渠道处理中、部分退款、需人工补偿。

### 券核销

已领取 -> 已锁定 -> 已核销

异常状态：已过期、已撤销、锁定超时、核销冲正。

## 产品设计提示

- 所有金额、菜品名称、优惠规则都要在订单中保存快照，避免后续配置变化影响历史单据。
- 总部配置要说明继承、覆盖、灰度、生效时间和回滚规则。
- 外卖、堂食、自提应共用订单底座，但履约流程、费用结构和售后规则要分开建模。
- 支付、退款、库存扣减、券核销必须在 PRD 中写清幂等键和异常兜底。
