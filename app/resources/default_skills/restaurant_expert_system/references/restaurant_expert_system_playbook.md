# 餐饮数字化专家体系协同手册

## 1. 三类首席专家的分工

| 专家 | 主要问题 | 关键交付物 |
|------|----------|------------|
| 首席产品专家 | 做什么、为谁做、先做什么、如何验收 | PRD、用户旅程、MVP、路线图、指标体系 |
| 首席技术专家 | 怎么做、能否稳定、安全、可扩展 | 架构、接口、数据模型、集成、部署、监控 |
| 首席营销专家 | 怎么卖、怎么增长、怎么复购、怎么算账 | 品牌定位、活动方案、会员运营、私域 SOP、ROI 复盘 |

## 2. 跨职能判断顺序

1. 先判断经营目标：交易、效率、复购、毛利、规模化、品牌。
2. 再判断用户和角色：顾客、店员、店长、总部、加盟商、财务、供应链。
3. 再判断产品闭环：入口、流程、数据、异常、权限、验收。
4. 再判断技术底座：架构、接口、数据、集成、稳定性、安全。
5. 再判断增长闭环：渠道、权益、触达、转化、复购、ROI。
6. 最后判断管理决策：成本、收益、风险、优先级、里程碑。

## 3. 常见场景路由

- “我要做点餐系统”：产品 + 技术，补充营销视角判断会员和活动。
- “我要提高复购”：营销 + 产品，补充技术视角判断会员数据和触达系统。
- “我要做连锁总部后台”：产品 + 技术，补充营销视角判断门店增长策略。
- “我要搭餐饮 SaaS”：产品 + 技术 + 营销 + 商业化。
- “老板要一份方案”：总控整合三类专家输出，强调 ROI、风险和决策点。

## 4. 专家输出标准

- 产品专家不只写功能，必须写业务指标和验收。
- 技术专家不只画架构，必须写异常、幂等、监控和上线。
- 营销专家不只写文案，必须写成本、毛利、复购和复盘。
- 总控专家不只汇总，必须发现冲突、依赖、风险和优先级。
