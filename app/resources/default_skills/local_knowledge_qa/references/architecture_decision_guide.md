# 餐饮系统架构决策指南

## 1. 单店与连锁

- 单店优先简化部署、降低学习成本、保证收银稳定。
- 连锁优先总部配置、门店继承、权限分层、数据汇总和巡店督导。

## 2. SaaS 与私有化

| 维度 | SaaS 多租户 | 私有化 |
|------|-------------|--------|
| 成本 | 共享资源，边际成本低 | 实施和运维成本高 |
| 安全 | 依赖租户隔离和权限 | 客户可控性强 |
| 迭代 | 统一升级 | 版本碎片风险 |
| 集成 | 标准 API 优先 | 定制接口更多 |

## 3. 一体化与中台化

- 早期产品优先交易闭环，不要过早拆分复杂中台。
- 多品牌、多渠道、多门店、多供应链场景出现后，再抽象商品、会员、营销、库存和数据中台。
- 中台边界必须服务前台业务，不应只为了技术抽象而拆分。

## 4. 同步与异步

- 影响用户即时反馈的操作使用同步接口。
- 支付回调、库存扣减、报表聚合、营销触达、外卖状态同步适合异步事件。
- 异步必须设计幂等、顺序、重试、死信和人工补偿。

## 5. 离线与在线

- POS、打印、KDS 要考虑门店弱网和局域网兜底。
- 离线订单要标记来源、时间、设备和同步状态。
- 离线支付要严格控制风险，不可绕过平台支付结果确认。
