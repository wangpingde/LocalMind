# 餐饮数字化技术专家手册

## 1. 技术目标排序

餐饮系统的第一目标是交易链路可靠：不中断、不丢单、不多扣款、不漏结算。其次才是高性能、扩展性和智能化。

## 2. 架构分层

- 终端层：POS、扫码点餐、小程序、KDS、打印机、电子秤、店员 App。
- 接入层：API 网关、鉴权、限流、签名、渠道适配。
- 业务层：订单、支付、退款、商品、会员、营销、库存、门店、员工、财务。
- 集成层：支付、外卖、团购、ERP、财务、短信、物流、硬件设备。
- 数据层：交易库、配置库、报表库、日志、对象存储、缓存、消息队列。
- 运维层：监控、告警、审计、备份、发布、灰度、故障演练。

## 3. 餐饮系统高风险点

- 支付回调重复、乱序、金额不一致。
- 外卖平台取消、退款、部分退款、平台状态和本地状态不一致。
- 高峰期下单和出餐链路拥堵。
- 门店弱网导致订单、支付、打印、KDS 不稳定。
- 总部配置错误同步到多门店。
- 库存和菜品沽清不同步导致超卖。
- 加盟商、门店、财务数据越权访问。

## 4. 必须设计的非功能能力

- 幂等：支付、退款、核销、库存扣减、外部回调。
- 补偿：失败重试、人工补单、对账修复、消息死信。
- 可观测：链路 ID、订单 ID、支付 ID、门店 ID、租户 ID 全链路日志。
- 灰度：按租户、品牌、门店、渠道、设备、员工分批发布。
- 回滚：代码回滚、配置回滚、数据修复、设备版本回退。
